# AC922 Qwen3.8 TP6 与 KVMem 长上下文推理

基于 1Cat-vLLM，在 IBM AC922 的 POWER9 / ppc64le 和六张 V100 16GB 上完成 Qwen3.8-27B 的 TP6 适配，并整合 KVMem，利用 CPU 内存承载历史 KV，支持 256K 长上下文推理。

本项目面向仍在使用 POWER9 与 V100 的部署者，整理适配结果、完整 OCI 镜像、部署与校验工具，以及真实代码负载的验收记录。当前交付包已通过单路 256K 和预热后的四路 256K；256K 独立冷四路测试未完成。

> 当前仓库发布项目说明、部署文档与性能结果。完整镜像、安装工具及测试载荷尚未上传；请勿将 git clone 视为取得完整可安装交付包。

## 两项核心工作

### Qwen3.8 的六卡张量并行适配

在 1Cat-vLLM 框架下完成 Qwen3.8-27B 的 TP6 部署、运行参数整合与实机验证，使用 AC922 的六张 V100。运行依赖、模型、tokenizer、原生库和编译缓存封装在 OCI 镜像中，配套安装、启动、停止和运行审计工具。

### 整合 KVMem 承载长上下文

通过 CPU 侧历史 KV 存储和外部前缀复用，扩展有限显存下的长上下文承载能力。单请求窗口为 262,144 token；实测每路输入 261,120 token，输出预算 1,024 token。四路历史上下文借助 CPU KVMem 存储，不能理解为四份完整 KV 同时常驻显存。

## 已验证结果

下表仅对应随包最终 v5 配置及固定真实代码测试输入。

| 场景 | 实际计算 prefill token/s | decode token/s | 结果 |
|---|---:|---:|---|
| 单路 261,120 token 冷输入 | 1,594.927 | 149.923 | 严格评分通过，零抢占 |
| 预热后四路，每路 261,120 token | 1,640.914 | 260.779 | 严格评分通过，真实四路运行，零抢占 |
| 独立冷四路 | — | — | 测试未完成 |

prefill 为引擎实际计算 token / 首 token 墙钟时间，含调度与首次 decode；四路 decode 为四条请求共同解码区间的合计吞吐。缓存命中不计入实际计算吞吐。

已完成的单路及暖四路共五条请求，20 个源码事实、640 个执行案例、40 个模型自拟测试全部通过。实际输出分别为单路 223 token、暖四路合计 868 token；没有测满每路 1,024 token 输出。这些结果只覆盖指定测试输入，不代表普适准确率，也不证明历史选择与 dense 推理逐值等价。

## 已知限制

- 256K 独立冷四路测试未完成；测试过程中触发 NUMA8 内存保护（最低约 2.782 GiB，低于 3 GiB 门槛），尚无完整结果。
- 5K / 30K / 100K 的完整性能矩阵尚未完成。
- 未验证断电恢复、宿主机重启和开机自启。
- AOT 编译缓存可复用，CUDA Graph 在每次新进程启动时重新捕获。
- 目前适用于同款硬件与对应软件环境，尚无跨架构、跨机型复现保证。
